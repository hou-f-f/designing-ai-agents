# 第2章学习笔记 — Agent 架构

> 学习目标：理解 AI Agent 的核心架构，掌握 PRA 循环，了解 Runtime VM、护栏模式和跨框架实现。

---

## 一、核心思想：PRA 循环

这是全书最重要的概念。

```
感知 Perception  →  推理 Reasoning  →  行动 Action
      ↑                                      |
      └──────────────── 结果反馈 ────────────┘
```

**传统软件** 是一次性的：输入 → 处理 → 输出，结束。  
**Agent** 是循环的：不断感知环境、思考、行动，直到完成目标。

## 三、逐文件讲解

### 📄 `argus/core.py` — 最简单的 PRA 实现

**概念**：一次完整的 感知→推理→行动 循环，53 行代码实现一个代码审查 Agent。

```python
def review_diff(diff: str, context: str = "") -> dict:

    # ── PERCEPTION（感知）──────────────────────────────
    # Agent "看到"的内容：系统角色 + 要审查的代码变更
    system = """You are Argus, an expert code reviewer.
Respond with JSON: {"summary": "...", "comments": [...]}"""
    user_msg = f"## Diff:\n```diff\n{diff}\n```"

    # ── REASONING（推理）──────────────────────────────
    # 把感知到的内容交给 LLM 分析，LLM 在这里"思考"
    response = client.messages.create(
        model="claude-sonnet-4-5-20250929",
        max_tokens=2048,
        system=system,
        messages=[{"role": "user", "content": user_msg}],
    )

    # ── ACTION（行动）────────────────────────────────
    # 解析 LLM 输出，返回结构化的审查结果
    text = response.content[0].text
    return json.loads(text)
```

**演示的测试场景**：diff 里藏了一个 SQL 注入漏洞：
```python
# 原来（安全）：
cursor.execute("SELECT * FROM users WHERE name = ?", (username,))

# 改成了（危险！SQL 注入）：
cursor.execute(f"SELECT * FROM users WHERE name = '{username}'")
```
Argus 应该输出 `severity: "critical"` 来标记这个漏洞。

> ⚠️ **注意**：这个函数只走了**一次** PRA，是最简化的形态，没有循环。

### 📄 `argus/coding_agent_simplified.py` — 带循环的 Agent

**概念**：真正的 Agent 会循环多次，LLM 自己决定什么时候完成任务。

```python
class CodingAgent:
    def __init__(self):
        self.tools = [ReadFile, EditFile, Bash, Search, Glob, Grep]  # 工具箱
        self.memory = ConversationHistory()                           # 记忆

    def run(self, user_task: str):
        self.memory.add_user_message(user_task)

        while True:                                      # ← 真正的循环！
            context = self.memory.get_context_window()  # 感知：读取历史
            response = self.llm.generate(context)       # 推理：LLM 决策

            if response.is_final_answer():
                return response.text                    # 完成，退出

            tool_result = self.execute_tool(response.tool)   # 行动：调工具
            self.memory.add_tool_result(tool_result)         # 更新记忆
```

**执行流程示例**（用户说"帮我重构这个函数"）：
```
① 感知：读取当前对话
② 推理：LLM 说"我需要先读文件"
③ 行动：调用 ReadFile
④ 更新记忆：文件内容存入历史
⑤ 感知：读取新上下文（包含文件内容）
⑥ 推理：LLM 说"好，可以修改了"
⑦ 行动：调用 EditFile
⑧ ... 直到完成
```

> 💡 **与 core.py 的区别**：core.py 一次性，这里是真循环，LLM 自主决定何时结束。

### 📄 `argus/runtime.py` — Runtime VM（概念性伪代码）

**注意：此文件是架构草图，不可独立运行**（引用了书中未定义的辅助类）。

**概念**：Runtime VM 是 Agent 的"操作系统"，负责所有基础设施。

```python
class AgentRuntime:
    def __init__(self, config):
        self.sandbox = Sandbox(...)           # 隔离沙箱：防止代码乱跑破坏系统
        self.state = StateManager(...)        # 状态管理：崩溃后能恢复进度
        self.mcp_host = MCPHost(...)          # 工具服务器：连接外部工具
        self.skills = SkillRegistry(...)      # 技能库：可复用能力
        self.monitor = ObservabilityLayer(...)# 监控层：日志、追踪、调试

    def execute_action(self, action):
        risk = self.classify_risk(action)     # 风险评估
        if risk.requires_approval:
            approval = self.request_human_approval(action)  # 高危操作须人工确认
            if not approval.granted:
                return ActionResult.blocked(approval.reason)

        with self.sandbox.isolated_context(): # 在沙箱中执行
            result = tool.invoke(action.parameters)

        self.state.checkpoint(action, result) # 保存检查点
        return result
```

| 组件 | 作用 |
|------|------|
| Sandbox | 隔离执行，防止破坏宿主系统 |
| StateManager | 持久化状态，支持崩溃恢复 |
| MCPHost | 连接外部工具（MCP 是 Anthropic 定义的工具协议） |
| SkillRegistry | 管理可复用技能 |
| ObservabilityLayer | 日志、监控、可观测性 |

### 📄 `patterns/openai_guardrails.py` — 护栏模式

**概念**：给 Agent 套上安全规则，输入和输出都要经过检查。

```python
agent = Agent(
    name="customer_service",
    instructions="Help customers with billing questions.",
    input_guardrails=[                          # 输入护栏
        InputGuardrail(no_pii_in_prompts),      # 不允许输入个人隐私信息
        InputGuardrail(topic_within_scope),     # 只处理账单相关问题
    ],
    output_guardrails=[                         # 输出护栏
        OutputGuardrail(no_hallucinated_prices),# 不允许捏造价格
        OutputGuardrail(professional_tone),     # 保持专业语气
    ],
)
```

就像工厂质检：**进料检查（输入护栏）** + **出货检查（输出护栏）**。

> ⚠️ 注意：四个回调函数（no_pii_in_prompts 等）是占位符，生产环境需要自己实现。

### 📄 `demos/langgraph_argus.py` — LangGraph 实现

**特点**：图结构，显式定义节点和状态，适合复杂流程控制。

```python
from langgraph.graph import StateGraph

class ReviewState(TypedDict):    # 定义状态结构
    diff: str
    review: str

def reason(state):               # 定义节点逻辑
    review = llm.invoke(f"Review: {state['diff']}")
    return {"review": review}

graph = StateGraph(ReviewState)
graph.add_node("review", reason) # 构建图
graph.set_entry_point("review")
agent = graph.compile()          # 编译成可运行的 Agent
```

---

### 两种框架对比

| | OpenAI Agents SDK | LangGraph |
|--|--|--|
| 风格 | 声明式，简洁 | 图结构，显式 |
| 适合 | 快速上手 | 复杂流程控制 |
| 核心抽象 | Agent + Runner | StateGraph + Node |
| 需要 API Key | OPENAI_API_KEY | 取决于用的 LLM |
