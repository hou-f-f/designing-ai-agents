# 第3章学习笔记 — 感知（Perception）

> 学习目标：理解 Agent 如何从海量信息中筛选出对当前任务最有用的内容。

---

## 一、核心问题

LLM 的上下文窗口有限（如 180,000 token），但真实项目信息远超这个量。
感知层解决的核心矛盾：

```
信息太多 ──→ 装不下         ──→ 模式1: Context Triage（按优先级筛）
装下了但还太长 ──→ 旧内容压缩   ──→ 模式2: Semantic Compaction（智能压缩）
不知道去哪找 ──→ 搜索策略      ──→ 模式3: Progressive Discovery（三阶段搜索）
格式五花八门 ──→ 统一表示      ──→ 模式4: Multimodal Fusion（格式融合）
```

## 三、模式1：Context Triage（上下文分诊）

**文件**：`patterns/context_triage.py`  
**问题**：信息太多，上下文窗口装不下，怎么决定保留什么？  
**类比**：急诊分诊，按病情严重程度排队，不是先到先得。

### 优先级 4 个等级

| 等级 | 值 | 对应内容 | 策略 |
|------|----|---------|------|
| CRITICAL | 4 | 系统提示、当前任务 | 绝对保留 |
| IMPORTANT | 3 | 当前文件、错误堆栈 | 尽量保留 |
| SUPPORTING | 2 | 背景文档、旧对话 | 有空间才放 |
| DEFERRABLE | 1 | 工具可取回的内容 | 不预加载 |

### 核心逻辑

```python
# 排序：优先级 > 是否错误 > 内容长度（都从大到小）
sorted_items = sorted(items, key=lambda x: (x.priority.value, 2.0 if x.is_error else 0.0, len(x.content)), reverse=True)

# 贪心填充：从高优先级开始装，装满为止
for item in sorted_items:
    if item.priority == Priority.DEFERRABLE:
        deferred.append(item)  # 直接推迟，不占窗口
        continue
    if tokens_used + item.token_estimate <= budget:
        selected.append(item)
        tokens_used += item.token_estimate
```

> 💡 **DEFERRABLE 不是"不重要"**，而是"工具随时可取，不需要预占窗口"。

## 四、模式2：Semantic Compaction（语义压缩）

**文件**：`patterns/semantic_compaction.py`  
**问题**：对话历史越来越长，超出预算怎么办？  
**类比**：会议纪要——不逐字记录，但关键决策必须保留。

### 三级压缩策略（逐步升级）

```
Level 0  总量 ≤ 目标    → 直接返回，不压缩
   ↓ 不够
Level 1  清除冗长工具输出 → 超500token的工具结果 → [Cleared: XX tokens]
   ↓ 还不够
Level 2  LLM 总结旧内容  → 非错误内容 → LLM摘要 | 错误原文保留
```

### 两个永远保护的原则

1. **最近 N 轮对话**：当前任务最相关，绝不压缩
2. **错误信息（is_error=True）**：错误堆栈一旦丢失很难恢复

### 关键：告诉 LLM 总结时保留什么

```python
self.llm.generate(
    "Summarize, preserving:\n"
    "- All decisions made\n"          # 决策
    "- All file paths and function names\n"  # 代码路径
    "- Current progress and remaining work\n"  # 进度
    "Discard: redundant tool outputs, abandoned approaches."
)
```

## 五、模式3：Progressive Discovery（渐进发现）

**文件**：`patterns/progressive_discovery.py`  
**问题**：Agent 不知道相关文件在哪里，如何高效找到？  
**类比**：侦探办案——广撒网 → 精读线索 → 顺藤摸瓜。

### 三个阶段

```
Phase 1: Forage（觅食）
  ├── 读项目说明文件（README.md、pyproject.toml）
  ├── 按关键词匹配文件名（glob）
  └── 在文件内容中搜索关键词（grep）
  → 输出：最多15个候选文件路径

Phase 2: Focus（聚焦）
  └── 完整读取前5个文件
  → 输出：文件内容列表

Phase 3: Deepen（深入）
  └── 从已读文件里提取 import，追踪读取被导入的文件（最多3个）
  → 输出：扩展后的内容列表
```

### 代价与收益

| 阶段 | 操作代价 | 信息密度 | 数量限制 |
|------|---------|---------|---------|
| Forage | 低（文件名/关键词） | 低 | 最多15个 |
| Focus | 中（完整读取） | 高 | 最多5个 |
| Deepen | 低（解析import） | 中 | 最多3个 |

## 六、模式4：Multimodal Fusion（多模态融合）

**文件**：`patterns/multimodal_fusion.py`  
**问题**：输入可能是文字、图片、JSON 混合，LLM 需要统一格式。  
**类比**：翻译官——把多国语言统一译成一种语言交给主席（LLM）。

### 三种输入的处理策略

```
TEXT（文字）       → 直接透传（LLM 原生格式）
STRUCTURED（结构化）→ 转成 Markdown 表格（紧凑 + 易读）
IMAGE（图片）
  ├── 需要空间理解？（layout/screenshot/diagram/UI...）
  │     YES → 保留原始图片字节（交给视觉模型）
  └──   NO  → 用 [描述文字] 替代（节省大量 token）
```

### decisions 字段的意义

```python
# FusedContext.decisions 记录每个输入的处理决策，例如：
["登录截图: spatial, keep image",
 "用户数据: structured to table",
 "任务描述: text passthrough"]
```

让感知过程**可解释**：知道 Agent 看到了什么、怎么处理的。

## 七、argus/perception.py — 四个模式的综合应用

**Argus 感知管道的完整流程**：

```
输入：diff + repo_root + budget
  ↓
Step 1  提取直接修改的文件       → relevance="modified"（优先级最高）
  ↓
Step 2  追踪 import 依赖         → relevance="imported"（理解上下游）
  ↓
Step 3  找对应测试文件           → relevance="test"（验证影响范围）
  ↓
Step 4  加载项目配置文件         → relevance="config"（了解代码规范）
  ↓
Step 5  按优先级排序，预算内贪心选取  ← 应用 Context Triage 原理
  ↓
输出：FileContext 列表 + PerceptionTrace（可观测统计）
```

### PerceptionTrace 的价值

```python
trace.files_discovered  # 发现了几个文件
trace.files_selected    # 选了几个
trace.files_dropped     # 丢了几个
trace.selectivity       # 选择率（越低说明信息过滤越激进）
trace.dropped_files     # 具体丢了哪些（调试用）
```

## 九、关键术语

| 术语 | 解释 |
|------|------|
| 上下文窗口 | LLM 一次能"看到"的最大 token 数量 |
| token | LLM 处理文本的基本单位，约 4个英文字符 = 1 token |
| DEFERRABLE | 可通过工具取回、不需要预加载进上下文的信息 |
| is_error | 错误信息标记，触发特殊保护（不压缩、优先保留） |
| selectivity | 感知选择率 = 选中token / 候选总token |
| 空间理解 | 需要分析图片中元素位置、布局关系的任务 |
